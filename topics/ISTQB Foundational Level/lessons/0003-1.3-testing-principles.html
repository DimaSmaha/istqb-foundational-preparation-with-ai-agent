1.3 Testing Principles

Seven principles, each a named exam trap. Learn the name, not just the idea — questions frequently ask "which principle is this?"

FL-1.3.1 (K2) Explain the seven testing principles

The seven principles

  1. Testing shows the presence, not the absence, of defects. Testing can show defects exist; it can never prove the test object is defect-free.
  2. Exhaustive testing is impossible. Testing every combination is infeasible except in trivial cases — use test techniques, prioritization, and risk-based testing to focus effort instead.
  3. Early testing saves time and money. Defects removed early don't cause further defects downstream. Start both static and dynamic testing as early as possible.
  4. Defects cluster together. A small number of components usually contain most defects or cause most failures (a Pareto-principle effect) — an important input for risk-based testing.
  5. Tests wear out. Repeating the same tests over and over becomes less effective at finding new defects — existing tests need modifying and new ones written (though repetition is still valuable for automated regression testing).
  6. Testing is context dependent. There's no single universally correct way to test — it's done differently in different contexts.
  7. Absence-of-defects fallacy. Fixing every defect found against specified requirements doesn't guarantee success — the system can still fail to meet users' actual needs. Verification alone isn't enough; validation matters too.
Two principles that are easy to mix up: "tests wear out" is about repeating the same tests losing effectiveness over time. "Absence-of-defects fallacy" is about fixing all known defects still not guaranteeing user satisfaction. They sound similarly pessimistic but address completely different problems.

Try to recall

Name the principle: a team can't test every possible combination of inputs, so they use equivalence partitioning and risk-based testing to prioritize instead. Which principle is this an application of?
Exhaustive testing is impossible
