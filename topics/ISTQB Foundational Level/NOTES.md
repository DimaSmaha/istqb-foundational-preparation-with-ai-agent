# Notes — ISTQB Foundational Level

> This is a trimmed example `NOTES.md`, kept short so the pattern is easy to copy. In real use, this file
> grows over the life of a topic: every locked decision, every `/teach-refactor` recheck, and a running
> progress log all get appended here, dated, so a future session (or a future you) can see what's already
> been decided and verified without re-deriving it.

## Locked-in decisions

- **Lesson granularity**: one lesson per 2-level syllabus section (1.1, 1.2, ... 6.2), not per fine-grained
  learning objective. A lesson pools mock-exam questions from all sub-LOs under its section.
- **Pacing**: build chapter by chapter across sessions, not all lessons at once.
- **Content restriction**: syllabus + sample exams only, no web search — a hard constraint from the
  learner, not a default.
- **Phrasing preference**: lean toward exact/near-verbatim syllabus phrasing in the "Knowledge" sections of
  lessons, not paraphrase — even if it makes lessons longer. Reasoning: mock exam wording tends to hew
  close to the syllabus's own wording, so studying the exact phrasing is more directly useful for
  recognizing exam questions. Still fine to paraphrase connective prose and build original comparison
  tables/diagrams as teaching scaffolding.
